# Bug Regression Analysis

This directory contains curated catalogs of bugs fixed in the original Snowflake
drivers, used to track UD regression coverage.

> **Not mirrored.** This directory is excluded from the public mirror
> (`snowflakedb/drivers`) via the Copybara denylist in
> `ci/mirroring/copy.bara.sky`.

## Files

| File | Description |
|---|---|
| `odbc.yaml` | Fixed bugs from the ODBC driver (~213 entries) |
| `python.yaml` | Fixed bugs from the Python driver (~302 entries) |
| `scripts/generate-report.py` | Generates `report.html` from the YAML catalogs |
| `report.html` | Generated HTML report — gitignored, regenerate locally |

## YAML schema

Each entry in the `bugs:` list has the following fields:

```yaml
- key: SNOW-XXXXXX          # Jira ticket key
  commit_date: 2024-03      # Year-month the fix was committed (YYYY-MM)
  summary: <text>           # One-line description copied from the Jira ticket
  status: Done              # Jira status at time of cataloging
  priority: High            # Jira priority (Blocker / Critical / High / Medium / Low)
  analysis_status: not_analyzed  # UD coverage status (see below)
```

### `analysis_status` values

| Value | Meaning |
|---|---|
| `not_analyzed` | Not yet checked against the UD |
| `covered` | Track 1 passed and every assertion has permanent UD test coverage |
| `gap` | Track 1 passed but one or more permanent coverage assertions are missing |
| `regression` | Track 1 failed — the UD has this bug |
| `not_implemented_in_ud` | The fix exists in the original driver but the UD does not implement this feature yet |
| `n/a` | No longer relevant (obsolete, superseded, or internal to the original driver) |

## How the catalogs were generated

The initial YAML catalogs were generated by querying Jira for all `Done` bugs
in the respective driver projects, filtered to tickets with a fix commit in the
driver's git history. Each entry was seeded with the ticket key, commit date,
summary, and priority from Jira; `analysis_status` was set to `not_analyzed`.

**The catalogs are not auto-updated.** When new bugs are fixed in the original
drivers, entries must be added. Keep entries in ascending `commit_date` order within the file.

## How entries are analyzed

Use the `bug-regression-coverage` Claude Code skill:

```
/bug-regression-coverage SNOW-XXXXXX
```

The skill follows a two-track approach:

- **Track 1** — writes and runs a temporary regression test against the UD to
  verify whether the bug is present right now.
- **Track 2** — audits the permanent UD test suite for coverage gaps and
  proposes new tests to fill them.

After analysis, the skill updates `analysis_status` in the appropriate YAML file.

## Regenerating the HTML report

```bash
python3 tests/bugs_analysis/scripts/generate-report.py
# writes tests/bugs_analysis/report.html
```

The report is self-contained HTML with per-driver tabs, status filter pills, and
sortable columns. Open it directly in a browser — no server needed.
